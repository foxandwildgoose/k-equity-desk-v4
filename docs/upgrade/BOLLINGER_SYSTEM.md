# Bollinger Trading Intelligence System

이 문서는 현재 코드의 계산·표시·저장·접근 범위를 설명한다. 실제 검사 명령, 결과, 브라우저 캡처와 미검증 항목은 [BOLLINGER_SYSTEM_VERIFICATION.md](./BOLLINGER_SYSTEM_VERIFICATION.md)에 별도로 기록한다. 이 설명만으로 실데이터 수신이나 운영 배포 검증이 완료되었다고 판단하지 않는다.

## 적용 범위와 기존 구조

기존 React / TypeScript / TanStack Start / Lightweight Charts 5.2.1 구조를 확장한다. 가격 차트의 공통 `ProChart`가 계산·표시·상태·알림을 연결하며, 기존 `bollinger()`, `sma()`, Wilder `rsi()`, 피벗 및 다이버전스 비교 함수를 재사용한다.

| 화면 | 연결 경로 | 대상 |
|---|---|---|
| 한국 주식 상세 | `stock.$ticker` → `TradingChart` → `ProChart` | 선택 주기의 실제 OHLCV |
| 한국 ETF 상세 | `etfs.$code` → `TradingChart` → `ProChart` | 국내 상장 가격 OHLCV |
| 미국 주식·ETF 상세 | `us.$symbol` → `TradingChart` → `ProChart` | 미국 가격 OHLCV, USD 및 뉴욕 시각 |
| 전체화면·워크스페이스 | `/chart` → 각 `ProChart` | 1/2/4분할, 각 종목·주기·레이아웃 scope |
| 일봉 스크리너 | `/bollinger` → 서버 스냅샷 → 공유 분석 엔진 | 사용자가 선택한 최대 10개 가격 상품 |

밸류에이션 배수, 공정가치, 수출입, 수급 전용, 신용·외국인·투신 하위 차트에는 새 거래 해석을 적용하지 않는다. 기존 SMA, RSI/MACD, 매물대, 수동 그리기, 비교 종목, 가격 알림과 키움 세 패널의 정의는 그대로 사용한다.

## 화면 조작

1. 가격 차트 가까이의 `Bollinger ON/OFF`가 관리되는 시스템의 밴드·음영, `%B`/`BBW` 보조 패널, 상태·Setup Quality, 패턴 배지와 신규 로컬 알림 평가를 함께 전환한다. 개별 설정은 보존된다.
2. `볼린저 설정`에서 밴드·음영, `%B`, `BBW`, 상태, 배지, 점수, 로컬 알림을 각각 선택한다. 배지는 기존 `차트 표시`의 **분석 신호**도 ON일 때 표시된다.
3. `보조 패널 펼침`은 자동/펼침/접기를 선택한다. 자동 상태는 넓은 단일 차트에서 펼치고 모바일·분할 차트에서는 접는다. 패널 높이는 기존 native pane의 상대 높이 비중으로 저장하며 고정 CSS 픽셀 높이가 아니다.
4. `트레이딩`은 5분/15분/1시간/일봉, `투자`는 일봉/주봉의 빠른 접근을 제공한다. 모드는 설명과 빠른 주기 버튼을 바꾸며 밴드 기간·배수를 자동 변경하지 않는다. 기존 전체 주기 선택 기능도 유지한다.
5. 상태 요약은 최신 봉 또는 십자선으로 선택한 과거 봉의 값·기준일·완료 여부를 구분한다. `Setup Quality`와 `확인 상태·BBW 범위·수급 출처`를 펼치면 구성 점수, 실제 입력값, 가용성, 이유를 확인할 수 있다.
6. 중심선 `자동`은 같은 종가 SMA20이 보일 때 BB(20, close, SMA)의 중복 중심선을 숨긴다. 다른 기간/소스이거나 강제 표시를 선택하면 중심선을 표시한다.
7. 색상은 테마 자동 또는 사용자 지정을 선택한다. 자동은 Light/Dark 전환을 따르고 명시한 사용자 색은 유지한다. 얇은 밴드 경계와 낮은 불투명도 음영은 캔들·SMA보다 두드러지지 않도록 구성한다.

마스터는 새 관리 시스템을 제어한다. 기존 지표 관리에서 사용자가 별도로 추가한 사용자 기간 BB와 애매한 중복 BB는 독립 지표로 보존하고 그 지표의 표시 토글로 관리한다. 마스터 OFF가 사용자 지표를 삭제하거나 기간·색·가시성 설정을 덮어쓰지 않는다.

## 공식·관례와 앱 휴리스틱

표준 밴드와 `%B`/BBW 공식은 일반 기술적 지표 정의다. 스퀴즈 분위수 임계값, 추세 허용 오차, 밴드 워크, W/M 패턴, 점수 가중치와 상태 결합은 **이 앱의 공개된 휴리스틱**이다. Fidelity/BlackRock/JPM 등의 독점 점수·수익 예측 공식을 재현했다고 주장하지 않는다.

방법 설명 참고 링크:

- [Fidelity — Bollinger Bands](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/bollinger-bands)
- [StockCharts ChartSchool — Bollinger Bands](https://chartschool.stockcharts.com/table-of-contents/technical-indicators-and-overlays/technical-overlays/bollinger-bands)
- [StockCharts ChartSchool — Bollinger BandWidth](https://chartschool.stockcharts.com/table-of-contents/technical-indicators-and-overlays/technical-indicators/bollinger-bandwidth)
- [StockCharts ChartSchool — Bollinger Band %B](https://chartschool.stockcharts.com/table-of-contents/technical-indicators-and-overlays/technical-indicators/bollinger-band-percent-b)

이 작업 환경에서 위 외부 페이지의 HTTPS 수신은 성공하지 못했다. 링크를 참고 출처로 제공하며 최신 본문을 읽거나 외부 문서와의 실시간 대조를 완료했다고 기록하지 않는다. 계산·프리셋 사양은 사용자 지시와 실제 코드가 기준이다.

### 밴드, %B, BBW

선택 가격 소스 `x`, 기간 `N`, 배수 `K`에 대해:

```text
Middle(t) = SMA(x, N)
σ(t)      = sqrt(Σ(x - Middle)² / N)         # 모집단 표준편차
Upper(t)  = Middle(t) + K × σ(t)
Lower(t)  = Middle(t) - K × σ(t)
%B(t)     = (Close(t) - Lower(t)) / (Upper(t) - Lower(t))
BBW(t)    = (Upper(t) - Lower(t)) / Middle(t) × 100
```

소스는 `close`, `hlc3=(high+low+close)/3`, `ohlc4=(open+high+low+close)/4`를 지원하고 중심 계산은 SMA다. 밴드가 다른 소스로 계산되어도 `%B`는 실제 종가의 상대 위치다. `%B`는 비율이며 0~1로 강제 제한하지 않는다. BBW는 퍼센트 포인트다. 0폭 밴드의 `%B`, 0 또는 음수 중심의 BBW, 필수 관측이 부족한 계산은 `null`이다. 누락·잘못된 수치를 0으로 바꾸지 않는다.

공유 `bollinger()`는 rolling population deviation을 사용한다. 큰 가격과 작은 변동성을 가진 자료에서도 `E[x²]-E[x]²`의 상쇄 오차를 피하도록 add/remove Welford 갱신과 주기적 재계산을 사용한다.

### 실제 BBW 분위수

종가의 가격 분위수인 기존 `BandCompare.pctRank`와 새 `bbwPercentile`은 별개다. 새 값은 현재까지 확보한 최근 `bbwLookback`개의 **유효 BBW**를 대상으로 한다. 현재 BBW도 표본에 포함한다.

```text
bbwPercentile = (현재 BBW보다 작은 표본 수 + 0.5 × 같은 표본 수)
                / 유효 표본 수 × 100
```

동률은 mid-rank로 처리한다. 최근 유효 표본이 기본 125개에 도달하기 전에는 분위수와 이에 의존하는 분류를 확정하지 않는다. 최소·최대 BBW와 표본 수는 별도로 제공한다. 중간 결측 BBW는 유효 표본 수에 포함하지 않으므로 125개 확보에 필요한 실제 봉 수가 더 길어질 수 있다.

## 완료봉, 시간대, 워밍업

기간은 **선택한 주기의 봉 개수**다. 기간 20은 분봉 20개, 일봉 20개, 주봉 20개처럼 각각 해당 주기의 봉 20개로 계산하며 일봉 밴드를 분봉·주봉에 복사하지 않는다. 분봉 평균을 세션 시작마다 초기화하지 않는다.

`useAnalysisChartData`가 기존 동일 주기 이력 경로를 사용하고 `sameChartPriceBasis` 검사를 통과한 추가 이력만 결합한다. `prepareSmaHistory`는 표시 구간 이전 봉을 유지하고 표시 구간의 정정 자료를 우선한다. 분석은 확장 이력에서 먼저 계산한 뒤 거래소 봉 키로 화면에 정렬한다. 확대·축소는 동일 봉의 계산값을 바꾸지 않는다.

분석에 필요한 기준 봉 수는 다음 중 최대다:

```text
SMA200 + 기울기 비교 봉 수
BB 기간 + BBW 유효 표본 수 - 1
RSI 기간 + 1
RVOL 기간
피벗 왼쪽 + 오른쪽 + 1
```

기본 BBW는 연속 유효 자료일 때 144번째 봉부터 125개 폭 표본이 생긴다. 기본 강한 장기 추세 분류는 SMA200의 5봉 기울기까지 필요하므로 최소 205봉이 필요하다. 화면은 최소 499개 또는 사용자 기간+BBW 표본+패턴 간격만큼의 이전 이력을 보존하려 하지만 실제 확보량을 넘어서 만들지 않는다.

완료 판단은 `bar-completion.ts`가 거래소 시각을 사용한다.

- 한국은 서울, 미국은 뉴욕 날짜/시각과 DST 변환을 사용한다.
- 분봉은 봉 시작 시각 + 선택 분 수가 현재 시각 이하인 경우 완료 후보가 된다.
- 일봉은 현지 오늘보다 이전 날짜여야 완료로 처리한다. 공급자 확정 플래그가 없으므로 오늘 종가는 장 마감 후에도 다음 현지 날짜까지 `PREVIEW`다.
- 주/월/년봉은 해당 기간 말이 현지 오늘보다 이전이어야 완료다. 휴장일·조기 폐장·공표 확정을 추측하지 않는다.
- 명시적인 `completed=false`는 시간 조건으로 덮어쓰지 않는다.

미완성 봉은 숫자·상태 미리보기를 제공할 수 있지만 확인 이벤트·알림을 발생시키지 않는다. 리플레이는 커서 이후 봉을 계산 이력에서 제거하고 신규 로컬 알림도 평가하지 않는다.

공급자 한계는 그대로 표시한다. Yahoo 1/3분 경로는 최대 7일, 5~30분은 최대 60일, 60분은 최대 2년 범위이며 Naver fallback은 일봉 약 1200/주봉 400/월봉 180개 제한이 있다. 신규 상장, 짧은 공급 이력, 변경된 가격 기준, 큰 사용자 기간/표본 구간으로 자료가 부족하면 `null`, 표본 부족 또는 부분 커버리지를 표시한다. 요청한 최대 기간·200봉·사용자 지정 워밍업 전부의 확보를 보장하지 않는다.

## 신호와 패턴 규칙

상단 접촉=매도, 하단 접촉=매수 규칙은 없다. 스퀴즈는 방향 중립이다. 방향은 별도의 종가 돌파·이탈과 추세·확인 자료를 통해 판단한다.

| 분류 | 구현 규칙 |
|---|---|
| 상단 돌파 | 현재 완료 종가가 현재 상단보다 높고, 직전 완료 종가는 직전 상단 이하 |
| 하단 이탈 | 현재 완료 종가가 현재 하단보다 낮고, 직전 완료 종가는 직전 하단 이상 |
| 실패 | 돌파/이탈 이후 기본 2개 완료봉 안에 종가가 해당 경계 안으로 복귀 |
| 상단 워크 | 최근 5개 완료봉 중 3개 이상 `%B≥0.8`, 최신도 충족, 모두 중심 이상, 중심 기울기 양수 |
| 하단 워크 | 대칭 규칙: `%B≤0.2`, 모두 중심 이하, 중심 기울기 음수 |
| 상승 추세 | 허용 오차를 넘는 `Close>SMA20>SMA60`, `Close>SMA200` |
| 강한 상승 | 상승 조건 + `SMA60>SMA120>SMA200`, 세 장기 SMA 정규화 기울기>0.001 |
| 하락·강한 하락 | 가격/평균 순서와 기울기의 대칭 조건 |

전체 필수 SMA가 확보되지 않으면 추세는 미확인이다. 상태 결합 우선순위는 실패 → 돌파/이탈 → 밴드 워크 → 확인 조건을 가진 돌파 준비 → 스퀴즈 → 추세 내 되돌림 → 중립 추세의 평균 회귀 관찰 → 혼조다. 되돌림·평균 회귀는 관찰 상태이며 자동 주문 권고가 아니다.

W/M와 `%B` 다이버전스는 공유 피벗 비교를 재사용한다. 피벗 주변의 왼쪽/오른쪽 확인 창에 실제 완료 OHLC가 있어야 한다. 신호 시각은 **오른쪽 확인 봉 또는 구조 확인 봉**이며 과거 피벗 날짜로 소급해 표시하지 않는다. 원래 피벗은 메타데이터로 따로 보존한다.

W는 근접한 두 저점, 첫 저점의 하단 근처 `%B`, 두 번째 저점의 더 강한 `%B`, 중간 반등이 있을 때 준비 상태다. 두 번째 저점이 반드시 더 낮거나 반드시 밴드 안이어야 한다고 강제하지 않는다. 준비 이후 완료 종가가 관측된 중간 반등 고점을 넘어야 구조 확인 이벤트가 생긴다. M은 대칭이다. 재시험 허용 비율은 기본 3%, 최대 피벗 간격은 60봉이며 이 앱의 규칙이다. 관측 중간 결측/미완성, 무효화된 고저점, 기간 만료는 확인을 중단한다.

정규 `%B` 다이버전스는 가격 저점 하락/%B 저점 상승 또는 가격 고점 상승/%B 고점 하락을 비교한다. 피벗의 오른쪽 확인 이전에는 이벤트를 내지 않는다. 이 기능이 수익성이나 반전을 보장하지 않는다.

## RSI, 거래량, 한국 수급

RSI 확인은 기존 Wilder RSI와 이전 완료봉 대비 기울기를 사용한다. 앱의 방향 확인 기준은 상승 RSI>55 및 양의 기울기, 하락 RSI<45 및 음의 기울기다.

일/주/월 RVOL은 `현재 거래량 / 현재 봉을 포함한 SMA(거래량, 20)`이다. 분봉은 동일 시각의 이전 20개 완료 세션 표본을 확보하면 동일 시간대 평균을 사용하고, 그렇지 않으면 rolling 봉 평균을 사용하여 `봉 평균 근사`라고 표시한다. 실제 0 거래량은 유효할 수 있지만 분모 0이나 누락/비정상 거래량은 확인 자료가 아니다.

한국 수급 확인은 기존 키움 원자료와 접근통제를 사용하며 별도 증권사 요청을 추가하지 않는다. 지표명을 정확히 유지한다:

- **외국인 보유비율 변화**: 5관측 거래일 전 대비 `wght` 변화, 단위 `%p`. 여섯 관측 거래일이 모두 확인되어야 한다. 외국인 순매수 수량이 아니다.
- **투신 순매수 수량**: 실제 일별 `invtrt`; 음수는 순매도다. 주/월 등에서는 가격 일별 관측 달력의 해당 구간이 모두 확인된 경우에만 기간 합계를 제공한다.

확인 자료는 `provider=kiwoom`, `environment=real`, 가격과 같은 시장 범위, 올바른 필드/단위, `dateBasis=trade-date`, 유효 파싱, `final!==false`를 요구한다. `availableAt`은 시간대가 명시된 ISO 시각(`Z` 또는 `±HH:MM`)이어야 하며 해당 봉의 기간 말/현재 평가 시각보다 늦으면 사용하지 않는다. `fetchedAt`을 공표시각으로 대신하지 않는다.

원자료 공표시각이나 거래일 기준이 불명확하면 기존 수급 패널에 값이 있더라도 이 분석의 과거 확인 점수에는 들어가지 않을 수 있다. 이는 오류를 0으로 숨기기보다 당시 알 수 있었는지를 구분하는 정책이다. 분봉에서 일별 수급을 확인 신호로 복사하지 않고 미국 종목은 국내 수급을 `not-applicable`로 처리한다. 신용잔고율 패널은 그대로 유지하지만 이 점수의 수급 항목을 대신하지 않는다.

## Setup Quality와 커버리지

`BOLLINGER_RULES`의 공개 앱 가중치는 추세 25, 변동성 20, 모멘텀 20, 거래량 15, 수급 10, 위험/보상 10이다. 상승과 하락 구조 모두 방향에 맞게 평가한다.

```text
normalizedScore = 가용 항목의 획득 점수 / 가용 최대 점수 × 100
coverage        = 가용 최대 점수 / 100
```

누락 항목은 0점으로 넣지 않고 가용 분모에서 제외한다. 외국인/투신 중 하나만 유효하면 수급의 해당 5점 부분만 가용하다. 미국의 국내 수급 제외와 근거 있는 목표가 미확보는 커버리지를 줄일 수 있다. 점수만 높은 저커버리지 결과를 완전한 확인으로 해석하지 않는다.

| 항목 | 점수 규칙 |
|---|---|
| 추세 | 강한 상승/하락 25, 상승/하락 18, 중립 8; SMA 미확보는 제외 |
| 변동성 | 극단 스퀴즈 20, 스퀴즈 18, 압축 14, 일반 5, 확장 20; 방향 중립 |
| 모멘텀 | 방향에 맞는 `%B` 위치 10 + RSI 레벨/기울기 10 |
| 거래량 | RVOL<0.8:0, 일반:5, ≥1.2:9, 설정 확인 기준 충족:12, ≥max(2, 확인 기준):15 |
| 수급 | 방향에 맞는 외국인 보유 변화 5 + 투신 순매수 수량 5; 각 가용성 별도 |
| 위험/보상 | 유효 비율<1:0, ≥1:3, ≥2:7, ≥3:10 |

위험/보상은 현재 확인된 돌파 종가, 반대 밴드 경계의 위험, 당시 확인된 이전 스윙 목표로 양의 위험·보상이 성립할 때만 계산한다. 가격·손절 경계·목표가 중 하나라도 0 이하이면 가용 항목에서 제외한다. 큰 사용자 배수로 음수가 된 밴드 경계를 유효한 손절가로 취급하지 않는다. 임의 목표 수익률이나 미래 스윙을 만들지 않는다. 설정·상태·점수는 성공 확률, 수익률 예측 또는 공식 기관 점수가 아니다.

## 로컬 알림

기존 `notifyAlert` 경로를 사용한다. 설정에서 로컬 볼린저 알림과 원하는 신호를 켜야 평가한다. 신규 완료 이벤트만 대상으로 하며 첫 활성화·재진입은 현재 완료봉을 baseline으로 삼아 오래된 역사 알림을 쏟지 않는다.

스퀴즈 → 상단 돌파/하단 이탈 → RVOL 확인의 3단계 메타데이터를 지원한다. 스퀴즈 워크플로는 기본 20개 완료봉 후 만료하고 실패가 확인되면 해제한다. 돌파와 거래량 확인이 같은 완료봉에서 충족되면 2·3단계가 같은 봉일 수 있다.

시장·종목·주기·모든 금융 규칙을 포함하는 identity와 stable event ID를 사용한다. 같은 브라우저의 워크스페이스 셀은 공유 ledger로 중복을 억제하며 브라우저 저장소에 최근 ID/기준일을 저장한다. 표시 색/모드 변화는 금융 identity를 바꾸지 않는다. 마스터 OFF, 알림 OFF, 리플레이, 로드 미완료에서는 신규 평가하지 않는다.

**열린 앱 세션용이다.** 서버 scheduler, 24시간 감시, 닫힌 브라우저의 push delivery 또는 여러 브라우저 간 완전한 중복 방지를 제공하지 않는다. 알림 전달은 기존 알림 설정·브라우저 권한에도 영향을 받는다.

## 일봉 스크리너 Phase 1

도구 메뉴의 `Bollinger Screener`에서 `KR:005930`, `KR:069500`, `US:NVDA`처럼 1~10개 종목을 지정하거나 관심종목의 처음 10개를 선택한다. **선택 종목 조회**를 눌러야 요청하며 페이지 방문·필터 변경만으로 여러 가격 이력을 가져오지 않는다.

서버는 기존 상품 메타데이터와 `fetchOhlc(day, 5y)`를 사용한다. 일별 날짜 정렬·중복/정정 처리를 한 실제 최신 최대 500개 봉에서 오늘의 미완성 봉을 제외하고 공유 엔진으로 스냅샷을 계산한다. 분석 설정은 공통 기본 20/2·BBW125·SMA200이며 개별 차트 사용자 설정을 자동 복사하지 않는다.

| 제한 | 실제 동작 |
|---|---|
| 종목 수 | 요청당 최대 10개, 중복 제거, 유효한 KR/US 코드만 |
| 조회 시작 | 사용자의 명시적인 조회 버튼 |
| 캐시 | 서버 인스턴스별 TTL 10분, 최대 256개 스냅샷 |
| 중복 요청 | 같은 캐시 키의 in-flight 요청 공유 |
| 동시 수신 | 인스턴스별 worker 1개; 다른 키의 동시 miss는 대기로 반환 |
| 간격 | 앞 수신 작업 종료 후 다음 수신까지 최소 1.5초 |
| 요청 예산 | 20초가 지나면 다음 종목을 새로 시작하지 않음 |
| 기존 HTTP 작업 | 진행 중인 기존 공급자 요청은 자체 timeout을 따름; 20초 강제 종료 보장이 아님 |
| 영속성 | 스냅샷은 일시 캐시이며 운영 이력 DB가 아님 |

캐시 키는 시장·종목·주기·설정과 서버 데이터 범위/검증된 접근 상태를 구분한다. 가격 분석은 기존 공개 가격 조회 모델이며 same-site 보호를 유지한다. 선택 수급은 기존 `assertKiwoomReadAccess` 정책을 통과한 PostgreSQL의 **읽기만** 수행한다. 스크리너에서 키움 OAuth/조회/수집이나 DB 마이그레이션을 실행하지 않는다. collector 공개 시장 자료 또는 owner 전용 설정의 정책을 우회하지 않는다.

필터는 BBW 분위수≤10%, 가격>SMA200, RVOL≥1.5, `%B≥1`, 상승/하락 추세, 양의 외국인 보유 변화, 양의 투신 순매수 수량, 사용자 점수 하한을 제공한다. 선택한 필터의 값이 결측이면 일치하지 않는다. 수급 중 한 값만 유효할 때는 그 값의 필터만 사용할 수 있다.

각 행에 종목·시장·일봉·기준일·출처·수신 시각·가용 상태를 제공한다. `recent`는 마지막 완료봉이 4달력일 이내라는 제한적인 기준이다. 실제 거래소 휴장 달력·공표 확정 검증을 대신하지 않는다. 오래된 이력, 미확보, 조회 실패/대기, SMA200 또는 BBW 워밍업 부족은 최신 점수 순위에서 제외하고 사유가 있는 별도 결과로 보여준다.

이 캐시·worker는 서버리스 replica 사이에서 공유되지 않는다. 전시장/대량 분봉 스캔, 분산 전체 호출 제한, 별도 서버 materialization 또는 24시간 수집 시스템을 구현했다고 주장하지 않는다. 운영 규모를 늘리려면 공유 materialization과 분산 호출 제한을 별도로 설계해야 한다.

## 저장·이전 설정·내보내기

기존 chart layout v2와 시장·상품·종목·주기·레이아웃 scope를 유지하고 `bollinger.version=1` 설정을 추가한다. 저장소 전체 삭제나 새 DB/ORM을 도입하지 않는다.

- 버전 설정이 있으면 명시적인 마스터 OFF, 개별 OFF, 파라미터, 색, 패널 펼침/높이와 알림 종류를 복원한다.
- 상품 유형과 현재 scope의 로드가 확인된 뒤 설정을 바꾸며, 명시적인 볼린저 변경은 기존 scoped 저장 계약으로 즉시 저장한다. 가격 시리즈 생성 시 OHLCV와 음영 primitive를 함께 연결하여 별도 효과가 오래된 가격 API를 붙잡지 않도록 한다.
- 보조 패널을 추가/제거할 때 native 가격축 폭이 달라져도 기존 차트 라이브러리의 `lockVisibleTimeRangeOnResize`로 논리적 시간 범위를 유지한다. 표시 토글 때문에 보이는 기간의 CSV·매물대 집계가 달라지지 않게 한다.
- 이전 layout의 첫 BB(20,2)를 관리 참조로 채택할 수 있다. 참조 인스턴스는 삭제하지 않고 중복 관리 렌더링을 피한다. 이전 가시성과 명시 색은 관리 overlay로 보존한다.
- 여러 기본처럼 보이는 BB나 사용자 BB 기간은 의도를 추측해 삭제하지 않는다. 별도 generic 지표는 기존 관리 기능을 유지한다.
- 관리 참조 지표를 기존 편집기에서 수정하면 연결 설정도 반영하고, 참조를 삭제하면 관리 밴드 표시를 해제한다.
- template 저장/불러오기 시 Bollinger 설정과 참조 UID를 함께 처리한다. drawings, SMA, RSI, 매물대, 가격 scale, 비교 종목과 다른 환경설정을 초기화하지 않는다.
- SSR, 손상 JSON, 저장소 차단·용량 부족은 기존 안전 저장 경로와 검증 함수로 처리한다.

PNG는 native 시리즈·pane·음영 및 기존 차트 요약 합성 경로를 사용한다. CSV는 원래 가격·지표·매물대·수급 영역을 보존하고 별도 Bollinger 영역에 날짜, 완료 여부, 밴드, `%B`, BBW/분위수/표본 수, 상태, RVOL 방식, 점수/coverage, 수급 가용성, 소스 및 설정을 기록한다. 원자료 숫자는 표시 OFF 때문에 삭제하지 않으며 누락은 빈 셀로 보존한다. 문자 셀의 spreadsheet formula injection도 방어한다.

| `src/components/charts/pro/ProChart.tsx` | 데이터→분석→pane/배지/알림/export 통합 |
| `src/lib/bollinger/screener.ts`, `src/server/bollinger-screener.ts` | bounded 스냅샷·필터·서버 조회 |
| `src/lib/bollinger-screener-fns.ts`, `src/routes/bollinger.tsx` | 안전한 서버 함수, 메뉴 페이지 |
| `scripts/qa-kiwoom-fixture.mjs` | 브라우저 테스트 전용 API→격리 PGlite→실제 수급 서버 경로 |

사용 가능한 검사 명령은 `npm run typecheck`, `npm run test:bollinger`, `npm test`, `npm run lint`, `npm run check:auth`, `npm run qa:bollinger`다. 작업 기준 main의 `npm run build`는 기존 환경 래퍼를 통한 Vite 빌드이며 **DB 마이그레이션을 실행하지 않는다**. `db:migrate`는 별도 명령이고 이 작업에서는 실행하지 않았다. 실제 실행 결과와 fixture/실데이터 구분은 [검증 기록](./BOLLINGER_SYSTEM_VERIFICATION.md)을 따른다.

새 Bollinger 시스템 자체의 DB migration은 없다. 테스트용 Kiwoom fixture는 메모리 PGlite에 기존 `0002_kiwoom_flow.sql`와 `0003_kiwoom_collection_targets.sql`을 적용하고 schema readiness를 검사한다. 이는 운영 DB에 해당 migration이 적용되어 있다는 증거나 서버 재시작 후 영속성 검증이 아니다.
