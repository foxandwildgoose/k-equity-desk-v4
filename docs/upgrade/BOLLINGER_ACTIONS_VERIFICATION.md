# Bollinger 실행·전략·차트 범위 수정 기록

확인일: 2026-10-09. 작업 기준 커밋: `b3db39e` (`fix: show selected stock Bollinger charts and explain screener results`). 이 문서는 이전 [선택 기업 분석 화면 기록](BOLLINGER_INVESTOR_VIEW.md)을 보완한다. 기존 Neon·Vercel Hobby·ProChart/Lightweight Charts를 재사용하며 DB 스키마와 migration 파일은 변경하지 않는다.

이번 수정은 **버튼을 누른 뒤 실제 결과가 달라지는지**, **가격·분석이 부족하면 실행이 자료 확보로 이어지는지**, **기업별 상황을 구분할 수 있는지**를 대상으로 한다. 확인한 결함과 코드 수정, 자동 검사, 운영 사이트 확인은 별도로 기록한다.

## 확인된 결함과 수정 경로

| 확인된 문제 | 기준 코드의 원인 | 수정 경로 |
| --- | --- | --- |
| 저장 편입 목록이 있는데 가격·분석이 없으면 실행해도 차트가 나오지 않음 | `execute()`는 `universeId`가 없을 때만 수집했다. 목록만 저장된 경우에는 검색만 했다. | 먼저 선택 범위를 조회하고 가격 미확보·최종 계산 미확보·오래된 계산·미완료 작업을 확인한다. 필요한 경우 같은 실행 의도로 권한 확인과 수집을 연결한다. 후보가 0개라는 이유만으로 수집하지 않는다. |

| 가격 없음과 최종 계산 없음이 같은 메시지임 | 전체 선택 목록과 가용성은 feature 테이블만 읽었다. | 저장 일봉 개수·최종 날짜를 같이 읽고 `가격 이력 미확보`, `최종 분석 대기`, `선택 버전 분석 대기`를 구분한다. 안전한 종목별 수신·계산 오류도 표시한다. |
| Squeeze Watch를 눌러도 종목 목록이 그대로임 | 전략만 바뀌어도 기본 표시 범위는 여전히 전체 선택이었다. | 전략 버튼은 해당 조건 일치 목록으로 전환한다. 선택 전략의 설명·일치 수·종목별 이유를 함께 바꾼다. `전체 선택`으로 돌아가면 미일치와 부족 자료도 확인할 수 있다. |
| 전략 미일치 이유가 항상 롱 사전 돌파 기준임 | 공통 이유 배열은 추세·저항 위치·RSI·건조 거래량의 롱 조건이었다. | 전략별 설명·검사 가능 여부·미충족 이유를 사용한다. 전략 판정에 필요한 값이 없으면 조건 미일치와 구분한다. |

| 페이지를 넘기면 선택한 차트가 다른 종목으로 바뀔 수 있음 | 초점 종목을 현재 inspection 페이지에서만 찾고 없으면 첫 종목을 선택했다. | 선택 범위에 귀속된 초점 종목을 보존한다. 다른 선택 범위와 섞이지 않도록 scope를 확인하고, 전략 일치 보기에서는 해당 보기의 종목을 사용한다. |
| 조건 일치 목록만 별도 차트로 이동하여 기준일이 달라짐 | 기존 `/chart` 연결은 조회 기준일을 전달하지 않았다. | 전체 선택과 조건 일치 목록 모두 동일한 내부 저장 가격 차트로 연결하여 선택 스냅샷·계산 버전·조회 기준일을 유지한다. |
| 전체 선택 목록에는 화면 정렬이 적용되지 않음 | inspection SQL은 편입 순위만 사용했다. | Long Readiness·저항 거리·RS 분위수 정렬을 전체 목록에도 적용하고 결측값은 뒤에 둔다. |
| 전략 일치 0개 상태에서 다시 실행해도 기업 차트가 사라진 채 남음 | 새 실행이 이전의 조건 일치 전용 보기 상태를 유지했다. | 실행은 전체 선택 기업 보기로 돌아간다. 전략의 후보가 0개여도 선택 기업의 차트와 미일치 이유를 볼 수 있다. |
| 다른 범위에서 갱신한 가격·정정 봉이 기존 분석에 반영되지 않을 수 있음 | 실행 판단은 분석 저장 여부와 4일 최근성만 확인했다. 공유 가격의 최신 날짜·수신 시각과 분석 시각을 비교하지 않았다. 기존 Yahoo 분석이 더 최신 Naver 자료를 놓치는 경우도 있었다. | 같은 기준의 정정·신규 가격과 최신 허용 공급자 기준을 비교해 재계산을 요청한다. 재계산 전까지 차트·종가·봉 수는 기존 분석의 기준을 유지하여 소스를 섞지 않는다. |

위 항목은 코드 추적과 재현으로 확인한 범위다. 모든 가능한 공급자 장애나 사용자의 운영 환경을 검증했다는 뜻은 아니다.

## 기준 커밋에서 재현한 실패

새 브라우저 검사로 `b3db39e`의 production 번들을 먼저 확인했다. 격리된 저장 자료와 테스트 응답을 사용했으며 운영 Neon 또는 실시간 시세를 사용하지 않았다.

- **가격·계산이 없는 기존 편입 목록 → 실행:** 권한 창을 기다리는 검사가 실패했다. 기준 구현은 검색만 수행했다.
- **native 최근 120봉 범위:** 실제 logical range의 폭은 124였고 요청한 120봉 검사가 실패했다. 버튼 상태만 확인한 검사로는 잡히지 않는 차이였다.
- **Squeeze Watch:** 다른 전략의 일치 종목만 표시해야 하는 검사에서 전체 20개 행이 그대로 남아 실패했다.

이 실패 기록은 수정 전 재현 증거이며 최종 통과 결과가 아니다. [실행 실패](artifacts/bollinger-actions/baseline-execute.json), [범위 실패](artifacts/bollinger-actions/baseline-range.json), [전략 전환 실패](artifacts/bollinger-actions/baseline-strategies.json)를 보존하고 같은 검사를 수정된 production 번들에서 다시 실행했다.

## 실행·보안·데이터 범위

- 자동 이어받기는 사용자가 **실행** 또는 **수집 이어받기**를 누른 작업에서만 시작한다. 페이지 방문·재로드·전략 전환만으로 수집하지 않는다.
- 요청은 동시에 보내지 않는다. 시간 예산 종료 응답만 이어가며 기본 최대 20회, 새 요청 시작 기준 30분, 동일한 저장 진행 상태 반복 제한을 적용한다. 이미 시작한 요청은 서버 시간 예산과 요청 타임아웃으로 제한한다. 영구 오류·권한 실패·조회 실패·일부 종목 오류는 자동으로 끝없이 재시도하지 않는다.
- 중지, 숨겨진 탭, 페이지 종료는 브라우저의 다음 요청을 중단한다. 이는 이미 시작한 서버 작업의 DB 저장을 되돌린다는 뜻이 아니다. 공유 DB lease와 서버 시간 예산은 계속 적용된다.
- 기존 운영자 쿠키는 HttpOnly·Secure·SameSite=Strict이며 같은 출처 검증을 유지한다. 권한 확인 입력값을 저장소·코드·URL·수집 요청 본문에 보관하지 않는다. 브라우저에는 허용된 공개 종목 코드와 안전한 상태 코드만 반환한다.
- 키움 App Key·App Secret, 기존 수급 세 지표, 로그인, 환경변수 값, 배포 설정은 변경하지 않는다. 이 분석 차트가 키움 개인 키를 소비하지 않는다.
- 차트는 같은 가격 기준의 저장 완료 일봉을 사용한다. 지표는 표시 범위 이전의 저장 이력을 포함하여 계산하고 없는 날짜·거래량·전략 값을 만들지 않는다. 최대 읽기 이력은 기존 5,000봉이며 실제 확보 기간을 표시한다.
- 최근성은 기존 4달력일 기준을 유지한다. 미확인 거래소 휴장일을 만들어 최신 상태로 바꾸지 않는다. 후보 0개와 자료 부족·조회 실패는 별도로 표시한다.
- 이번 변경은 기존 Neon 테이블과 Vercel 설정을 재사용한다. 새 DB·유료 서비스·Node 설치·키 재등록·새 migration 적용은 요구하지 않는다.

브라우저 검사는 Light/Dark, 데스크톱·태블릿·모바일, 실제 canvas와 native time scale, 실행·권한 확인·취소·이어받기·종목 선택·전략 전환·날짜·페이지·PNG/CSV를 대상으로 한다. 테스트용 저장 자료는 `QA SYNTHETIC`으로 구분하며 서비스 데이터로 삽입하지 않는다.

증거는 [artifacts/bollinger-actions](artifacts/bollinger-actions/)에 저장했다. `actions-initial.json`에는 고정 200ms 대기 때문에 비동기 페이지 결과를 읽기 전에 발생한 3개 실패가 그대로 남아 있다. 실제 행 수와 종목 ID를 기다리는 검사로 수정한 뒤 해당 3개 조합만 재검사한 결과가 `actions-corrected.json`이다. `actions-latest.json`은 마지막 공급자 기준 SQL 수정 뒤 새 production 빌드의 별도 전체 동작 검사다. 통과 검사로 원래 실패 기록을 덮어쓰지 않았다.

기존 Screener 회귀 fixture도 새 최근성 검사와 격리 계약에 맞췄다. 가격을 저장하기 전에 계산을 저장하던 순서를 바로잡고, 매 화면 조합에서 기본·사용자 계산 버전과 이전 조합이 복구한 KOSDAQ 가격을 함께 초기화했다. 검사 도중 한국시간 자정을 지나 4일 기준 경계 fixture가 5일 된 자료로 바뀐 실패는 브라우저 날짜를 해당 fixture 날짜로 고정하여 재검사했다. 타이머는 실제로 진행하며 오래된 자료를 제외하는 앱 정책은 변경하지 않았다. `legacy-initial.json`과 `legacy-before-clock-pin.json`에는 이전 실패를 그대로 남겼다. 최종 6개 조합의 실제 통과 기록은 [검사별 manifest](artifacts/bollinger-actions/final-case-manifest.json)에서 확인할 수 있다. Light 데스크톱은 완료 stdout·캡처 증거, Light 태블릿은 전체 결과 JSON, 나머지 4개 조합은 `legacy-clock-pinned.json`으로 구분했다.

전체 차트가 보이는 캡처: [Light 120봉](artifacts/bollinger-actions/light-120.png), [Light 250봉](artifacts/bollinger-actions/light-250.png), [Dark 120봉](artifacts/bollinger-actions/dark-120.png), [Dark 250봉](artifacts/bollinger-actions/dark-250.png). 전략별 목록: [Squeeze Watch](artifacts/bollinger-actions/squeeze-dark.png), [Triggered](artifacts/bollinger-actions/triggered-dark.png). 수치는 모두 화면에 표시된 `QA ACTION SYNTHETIC — NOT MARKET DATA` 검사 자료다.

## 완료 상태와 운영 확인

| 단계 | 상태 |
| --- | --- |
| 코드 수정 | 완료. 실제 실행·권한·수집·저장 조회·전략·차트 범위 경로 변경 및 회귀 테스트 포함 |
| 격리 저장 자료·production 브라우저 자동 검사 | 완료. 최종 전체 앱 605개·Screener 동작 6개 조합·기존 Screener 회귀 6개 조합·최신 production 재검사·HTS 6개 조합 통과 |
| 운영 Neon 저장 자료와 실제 공급자 수신 | 이 환경에서 검증하지 않음 |
| 실제 Vercel Production 사이트의 버튼·차트 | 새 커밋 배포 후 검증 필요 |

현재 실행 환경에는 사용자의 운영 Neon 연결과 운영자 인증정보가 주입되지 않았다. 운영 사이트 접속은 이 환경의 네트워크 정책에도 영향을 받는다. 로컬 production 번들의 자동 검사가 통과하더라도 실제 Vercel·Neon의 수집 성공을 보장한 것으로 기록하지 않는다. 기존 사용자 설정이 잘못되었다고 단정하지 않는다.

GitHub 반영 뒤에는 새 커밋의 Vercel **Production → Ready**를 확인하고 기존 `/bollinger` 페이지를 새로고침한다. KOSDAQ Top20 등 필요한 범위를 고르고 **실행**을 누르면 된다. 권한이 필요한 경우 화면에 표시된 기존 운영자 확인 절차를 진행한다. 전체 기업 이름·상황·가격 차트가 나타나는지, 전략 버튼으로 일치 기업이 바뀌는지, 최근 120/250봉 버튼으로 실제 가격 구간이 바뀌는지를 확인한다. 신규 설치나 DB 구조 변경은 이번 변경의 다음 단계가 아니다.
